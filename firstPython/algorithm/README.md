# 알고리즘 (Algorithm)

기초 알고리즘 개념 정리.

## 재귀 (Recursion)

함수가 자기 자신을 다시 호출해서, 문제를 더 작은 문제로 쪼개 해결하는 방식.

- **반복(iterative)**: `while`/`for` 반복문으로 값을 계속 갱신하며 계산
- **재귀(recursive)**: 함수가 자기 자신을 호출, 종료 조건(base case)에 도달하면 멈춤

```python
# 반복
def factorial(n):
    the_product = 1
    while n > 0:
        the_product *= n
        n -= 1
    return the_product

# 재귀
def factorial_2(n):
    if n == 0:
        return 1
    return n * factorial_2(n - 1)
```

## 탐색 알고리즘 (Search)

| 알고리즘 | 개념 | 시간복잡도 |
|---|---|---|
| 선형 탐색 (Linear Search) | 리스트를 처음부터 끝까지 하나씩 순회하며 비교 | O(n) |
| 이진 탐색 (Binary Search) | **정렬된** 리스트를 대상으로, 중간값과 비교해 탐색 범위를 절반씩 좁혀나감 | O(log n) |

이진 탐색은 데이터가 정렬돼 있을 때만 쓸 수 있고, 그 대신 선형 탐색보다 훨씬 빠름.

### 직접 구현 vs 파이썬 내장 기능

| 하고 싶은 것 | 직접 구현 | 파이썬 내장 기능 |
|---|---|---|
| 리스트/문자열에 값이 있는지 확인 | `linear_search()` | `in` 키워드 (`값 in 리스트`) |
| 정렬된 리스트에서 값 찾기 | `binary_search()` | `bisect.bisect_left()` |

`bisect_left`는 값이 있는지 없는지(True/False)가 아니라, "정렬 순서를 유지하려면 몇 번째 인덱스에 넣어야 하는가"를 반환하므로, 있는지 확인하려면 인덱스 범위 체크(`index < len(list)`)와 값 비교(`list[index] == target`)를 추가로 해줘야 함.

## 정렬 알고리즘 (Sort)

| 알고리즘 | 개념 | 시간복잡도 |
|---|---|---|
| 버블 정렬 (Bubble Sort) | 인접한 두 원소를 비교해서 순서가 틀리면 교환, 이를 반복 | O(n²) |
| 삽입 정렬 (Insertion Sort) | 리스트를 정렬된 구간 / 안 된 구간으로 나누고, 안 된 구간에서 하나씩 꺼내 정렬된 구간의 알맞은 위치에 삽입 | O(n²) |
| 병합 정렬 (Merge Sort) | 원소 1개가 남을 때까지 재귀적으로 반씩 쪼갠 뒤, 두 조각을 비교하며 다시 병합(merge) | O(n log n) |

### 직접 구현 vs 파이썬 내장 기능

| 하고 싶은 것 | 직접 구현 | 파이썬 내장 기능 |
|---|---|---|
| 리스트 정렬 | `bubble_sort()`, `insertion_sort()`, `merge_sort()` | `list.sort()` (원본 변경) / `sorted(list)` (새 리스트 반환) |

파이썬 내장 정렬은 **Timsort**(병합 정렬 + 삽입 정렬을 결합한 알고리즘)를 사용하며, 실무에서는 대부분 이 내장 함수를 사용함. 직접 구현은 알고리즘의 동작 원리와 시간복잡도를 이해하기 위한 학습 목적.

## 문자열 알고리즘 (String)

| 알고리즘 | 개념 | 시간복잡도 |
|---|---|---|
| 애너그램 (Anagram) | 공백 제거 + 소문자로 통일한 뒤, 두 문자열을 각각 정렬해서 그 결과가 같은지 비교 | O(n log n) |
| 팰린드롬 (Palindrome) | 문자열을 뒤집어서(`[::-1]`) 원본과 같은지 비교 | O(n) |
| 리스트 축약으로 조건에 맞는 원소 뽑기 | `[c for c in s if c.isdigit()]`처럼 조건을 만족하는 원소만 걸러 새 리스트 생성 | O(n) |
| 시저 암호 (Caesar Cipher) | 각 문자의 알파벳 내 위치를 구해 key만큼 이동시키고(`% 26`으로 순환), 이동된 위치의 새 문자로 치환 | O(n) |

- **애너그램이 O(n log n)인 이유**: `replace`, `lower`는 O(n)이지만 `sorted()`가 내부적으로 비교 정렬(Timsort)을 쓰기 때문에 O(n log n)이 걸리고, 이게 전체 시간을 지배함(dominant term).
- **팰린드롬/리스트 축약이 O(n)인 이유**: 문자열 전체를 한 번씩만 훑기(슬라이싱으로 뒤집기, 혹은 조건 검사하며 순회) 때문에, 정렬 같은 추가 비용 없이 딱 원소 개수만큼만 연산함.
- **시저 암호가 O(n)인 이유**: 입력 문자열 길이 n만큼 한 글자씩 순회(`for c in a_string`)하는데, 그 안에서 하는 `c in uppercase`, `uppercase.index(c)` 같은 연산은 알파벳이 항상 26글자로 고정돼 있어서 입력 크기와 무관한 상수 시간(O(1))으로 취급됨. 그래서 전체는 O(26n) = O(n).
  - 단, `encrypt += ...`처럼 반복문 안에서 문자열을 계속 이어붙이는 방식은 문자열이 불변(immutable)이라 매번 새 문자열을 복사해서 만들기 때문에, 이론적으로는 반복마다 O(n) 복사 비용이 들어 전체 O(n²)이 될 수 있음. CPython은 이런 패턴을 최적화해서 실제로는 O(n)에 가깝게 동작하지만, 이는 구현체(CPython)에 의존하는 최적화이지 언어 차원의 보장이 아님. 안전하게 O(n)을 보장하려면 리스트에 문자를 담아뒀다가 마지막에 `''.join(리스트)`로 합치는 방식을 쓰는 게 좋음.

## 비트 연산 (Bit Operation)

| 연산자 | 개념 | 예시 |
|---|---|---|
| AND (`&`) | 두 비트가 모두 1이면 1 | `5 & 3` → `1` |
| OR (`\|`) | 둘 중 하나라도 1이면 1 | `0b10 \| 0b11` → `3` |
| XOR (`^`) | 두 비트가 서로 다르면 1 | `0b10 ^ 0b11` → `1` |
| NOT (`~`) | 모든 비트 반전, 2의 보수 표현이라 `~n == -(n+1)` | `~5` → `-6` |
| 왼쪽 시프트 (`<<`) | 비트를 왼쪽으로 밀기 (2를 곱하는 효과) | `1 << 2` → `4` |
| 오른쪽 시프트 (`>>`) | 비트를 오른쪽으로 밀기 (2로 나누는 효과, 소수점 버림) | `8 >> 2` → `2` |

- **`&`(비트 AND)와 `and`(논리 AND)는 다르다**: `and`는 값 전체를 참/거짓으로 보고 판단해서 둘 중 하나의 값을 그대로 반환하지만(`5 and 3` → `3`), `&`는 이진수 자릿수 하나하나를 따로 비교해서 새 숫자를 만든다(`5 & 3` → `1`). `|`/`or`도 같은 관계.
- **`n & 1`로 짝수/홀수 판별**: 이진수 맨 마지막 자리(1의 자리)만 뽑아내는 것과 같아서, `0`이면 짝수 `1`이면 홀수. `is_even(n)`은 `not n & 1`로 구현 (`&`가 `not`보다 우선순위 높아서 `not (n & 1)`로 계산됨).
- **`n & (n-1) == 0`으로 2의 거듭제곱 판별**: 2의 거듭제곱은 이진수로 1비트가 딱 하나뿐이라, `n-1`을 하면 그 비트가 0이 되고 아래 자리는 전부 1로 채워져서 겹치는 비트가 없어짐. `is_power(n)`이 이 트릭을 사용하는데, `n=0`인 경우 `0 & -1 = 0`이 되어 실제로는 2의 거듭제곱이 아닌데도 `True`를 반환하는 예외 케이스가 있음(별도 처리 안 돼 있음).

## 수학 알고리즘 (Math)

| 알고리즘 | 개념 | 시간복잡도 |
|---|---|---|
| 피즈버즈 (FizzBuzz) | 1~n까지 순회하며 15의 배수는 "FizzBuzz", 3의 배수는 "Fizz", 5의 배수는 "Buzz", 그 외는 숫자 그대로 출력 (나머지 연산자 `%`로 배수 판별) | O(n) |
| 최대공약수 - 브루트포스 (GCD) | 두 수 중 작은 수까지 1씩 증가시키며 두 수를 동시에 나눠보고, 나누어떨어지는 가장 큰 수를 갱신 | O(min(a, b)) |
| 최대공약수 - 유클리드 알고리즘 | `gcd(a, b) = gcd(b, a % b)` 성질을 이용해 나머지가 0이 될 때까지 자리바꿈+나머지 계산을 반복 | O(log(min(a, b))) |
| 소수 판별 - 브루트포스 | 2부터 n-1까지 하나씩 나눠봐서 한 번이라도 나누어떨어지면 소수가 아님 | O(n) |
| 소수 판별 - 제곱근 최적화 | 약수는 항상 `작은 약수 x 큰 약수 = n` 짝으로 나오고, 이 짝은 `sqrt(n)`을 기준으로 대칭이므로 `sqrt(n)`까지만 나눠봐도 충분함 | O(√n) |
| 소수 목록 - 에라토스테네스의 체 | 2부터 n까지 전부 "소수"라고 가정해두고, 소수를 하나 찾을 때마다 그 배수를 전부 지워나가서 안 지워진 것만 소수로 남김 | O(n log log n) |

- **`%`(나머지 연산자)로 배수 판별**: `A % B == 0`이면 "A를 B로 나눴을 때 나머지가 없다" = A는 B의 배수라는 뜻. FizzBuzz에서는 3과 5 둘 다의 배수(15의 배수)인 경우를 **가장 먼저** 체크해야, "Fizz"/"Buzz"만 출력되고 "FizzBuzz"가 안 나오는 실수를 피할 수 있음.
- **경계 조건(edge case) 처리**: 최대공약수를 구할 때 입력값이 음수이거나 0이면 일반적인 반복문 로직이 깨짐. `gcf()`는 음수가 들어오면 `raise ValueError(...)`로 즉시 에러를 발생시켜 잘못된 계산을 막고, 0이 들어오면 "0과 n의 최대공약수는 n"이라는 성질에 따라 남은 수를 바로 반환함.
- **`raise`/`ValueError`**: `raise`는 강제로 에러를 발생시켜 그 즉시 함수(또는 프로그램)를 멈추는 키워드. `ValueError`는 "값 자체가 잘못됐다"는 뜻의 파이썬 내장 에러 타입이고, 괄호 안 문자열은 에러 발생 시 표시되는 메시지.
- **유클리드 알고리즘이 O(log(min(a,b)))인 이유**: 나머지 연산(`%`)을 두 번 거칠 때마다 숫자가 최소 절반 이하로 줄어드는 성질이 있어서, 병합정렬처럼 "반씩 줄어들면 로그"라는 원리가 그대로 적용됨. `while y != 0: x, y = y, x % y`에서 `y`가 0이 되는 순간(=나머지가 0) 멈추고, 그 직전 `x`가 최대공약수.
- **`sqrt(n)`까지만 확인해도 되는 이유**: n의 약수는 항상 `작은 약수 x 큰 약수 = n` 형태의 짝으로 나옴 (예: `35 = 1x35, 5x7`). 이 짝은 항상 `sqrt(n)`을 기준으로 대칭 위치에 있어서(`sqrt(35)≈5.9`, `5<5.9<7`), 작은 쪽 약수(`2~sqrt(n)`)만 확인해도 큰 쪽 약수는 자동으로 같이 밝혀짐.
- **에라토스테네스의 체 동작 방식**: 숫자 하나하나가 소수인지 처음부터 계산하는 대신, `[True]*(n+1)` 리스트로 "일단 전부 소수"라고 가정해두고 시작. 소수를 하나 찾을 때마다(`is_prime_list[i]`가 아직 `True`) 그 배수(`range(i*i, n+1, i)`)를 전부 `False`로 지워나가서, 끝까지 `True`로 남은 인덱스만 소수로 반환(`enumerate()`로 인덱스와 값을 함께 순회).
