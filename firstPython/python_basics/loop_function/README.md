## 리스트 기초 & 코딩테스트용 메서드 (`list_data_structure.py`)

| 메서드/문법 | 하는 일 |
|---|---|
| `리스트[i] = 값` | 인덱스로 값 변경 |
| `.append(값)` | 맨 뒤에 추가 |
| `+=` | 리스트끼리 이어붙이기 |
| `.insert(i, 값)` | 원하는 인덱스에 끼워넣기 |
| `[-1]` | 마지막 요소 (음수 인덱스는 뒤에서부터) |
| `.pop()` / `.pop(i)` | 마지막(또는 지정 인덱스) 삭제 + 그 값을 반환 |
| `len(리스트)` | 길이 |
| `값 in 리스트` | 포함 여부 확인 |
| `리스트[시작:끝]` | 슬라이싱, 끝 인덱스는 미포함 |
| `리스트[::-1]` | 뒤집기 |
| `.count(값)` | 그 값의 개수 |
| `.index(값)` | 그 값이 처음 나오는 위치 |
| `.remove(값)` | 값으로 첫 번째 항목만 삭제 (인덱스 아님) |
| `.extend(리스트)` | 다른 리스트를 뒤에 통째로 붙임 (`+=`와 동일) |
| `.sort()` / `.sort(reverse=True)` | 원본을 오름차순/내림차순 정렬 (반환값 없음) |
| `sorted(리스트)` | 원본은 그대로, 정렬된 새 리스트 반환 |
| `.reverse()` | 원본을 뒤집음 (반환값 없음) |
| `min()` / `max()` / `sum()` | 최솟값 / 최댓값 / 합 |
| `"구분자".join(리스트)` | 문자열 리스트를 하나의 문자열로 합침 |

- `.sort()`/`.reverse()`는 **원본을 직접 바꾸고 반환값이 없음**, `sorted()`는 **원본을 안 건드리고 새 리스트를 반환**함 — 둘을 헷갈리면 원본이 예상과 다르게 바뀌어 있거나, `None`을 리스트인 줄 알고 쓰다가 에러가 남
- `.remove(값)`은 인덱스가 아니라 **값**으로 지우는 것이며, 같은 값이 여러 개면 **가장 앞의 것 하나만** 지움

## 중첩 리스트 (Nested List)

리스트 안에 또 다른 리스트가 요소로 들어있는 것.
```python
alphabets = [["a", "b"], "c"]
print(alphabets[0])     # ['a', 'b'] -> 첫 번째 요소 자체가 리스트
print(alphabets[0][0])  # 'a'        -> 안쪽 리스트의 원소는 인덱스를 두 번 써서 접근
```
`alphabets[["a,b"], "c"]`처럼 대괄호 안에 콤마로 값을 나열하면 **튜플로 인덱싱하는 것**으로 해석되어 `TypeError: list indices must be integers or slices, not tuple`가 남 — 중첩 리스트를 만들 땐 `[[...], ...]`처럼 **대괄호를 겹쳐서** 써야 함.

## for-in vs range() vs enumerate() (`loop.py`)

- `for 값 in 리스트/문자열`: **값 자체**가 필요할 때, 인덱스는 필요 없음
- `for i in range(N)`: **인덱스 번호**가 필요하거나, 값 상관없이 **정해진 횟수**만큼 반복할 때
- `for i, 값 in enumerate(리스트)`: **인덱스와 값이 둘 다** 필요할 때, `range(len(리스트))`보다 깔끔한 방법
- `range(start, stop, step)`: `stop`은 항상 미포함, 인자 1개(`range(N)`)면 `start`가 자동으로 0

## FizzBuzz — 조건 순서 (`fizzbuzz.py`)

조건이 서로 겹칠 수 있으면(예: 15는 3의 배수이면서 5의 배수), **더 좁고 구체적인 조건(동시조건)을 항상 먼저** 검사해야 함. `elif`는 위에서부터 하나 걸리면 그 즉시 멈추기 때문에, 넓은 조건을 먼저 두면 좁은 조건이 걸릴 기회를 가로채 버림.
```python
# ! 틀림: i=15면 "fizz"만 출력되고 "fizzbuzz"까지 도달 못 함
if i % 3 == 0:
    print("fizz")
elif i % 3 == 0 and i % 5 == 0:
    print("fizzbuzz")

# * 맞음: 동시조건(둘 다 만족)을 가장 먼저 체크
if i % 3 == 0 and i % 5 == 0:
    print("fizzbuzz")
elif i % 3 == 0:
    print("fizz")
```

## 랜덤 비밀번호 생성기 (`password_pro.py`)

- `string.ascii_lowercase`/`ascii_uppercase`/`digits`/`punctuation`: 알파벳/숫자/특수문자를 일일이 입력할 필요 없이 미리 제공되는 문자열
- `random.randint(0, len(리스트) - 1)`로 인덱스를 뽑아 `리스트[인덱스]`로 값 꺼내기 — `randint`는 양 끝 **포함**이라 `-1` 없이 `len(리스트)`까지 뽑으면 존재하지 않는 인덱스라 `IndexError`가 남
- `random.choice(리스트)`를 쓰면 인덱스 계산 없이 랜덤 값 하나를 바로 뽑을 수 있어 더 간단함
- `random.shuffle(리스트)`로 완성된 문자 리스트의 순서를 섞음 (원본을 직접 바꿈, 반환값 없음)
- `"".join(리스트)`로 문자 리스트를 하나의 문자열(비밀번호)로 합침
- `[str(i) for i in range(10)]`(리스트 축약): `numbers = []; for i in range(10): numbers.append(str(i))`를 한 줄로 줄인 것

## while문 (`while_loop.py`)

- `while 조건:` — 조건이 참인 동안 반복, `for`와 달리 반복 횟수를 미리 몰라도 됨 (조건이 거짓이 될 때까지)
- `while True:` — C언어의 `while(1)`과 동일한 무한 루프, 조건 없이 항상 참. **`break`로 직접 빠져나오지 않으면 영원히 반복**됨
- 코딩테스트에서는 "특정 조건을 만족할 때까지 반복"을 표현할 때 `while True:` + `break` 조합을 자주 씀

## 문자열 뒤집기 4가지 방법 (`string_reverse.py`)

| 방법 | 핵심 |
|---|---|
| `list(value); .reverse(); "".join()` | 리스트로 바꿔서 원본 순서를 뒤집은 뒤 다시 문자열로 합침 |
| `"".join(reversed(value))` | `reversed()`가 이터레이터를 반환, `join()`으로 값을 꺼내 이어붙임 (`list()`로 감쌀 필요 없음, `join()`은 이터레이터를 직접 받을 수 있음) |
| `for i in range(len(value)-1, -1, -1): temp.append(value[i])` | 마지막 인덱스부터 0까지 거꾸로 순회하며 직접 인덱싱 |
| `while len(value_list) > 0: temp.append(value_list.pop())` | `pop()`은 기본적으로 **맨 뒤 원소**를 꺼내면서 제거 → 이걸 반복하면 자연히 뒤집힌 순서로 쌓임 |

- **이터레이터(iterator)**: 값을 미리 다 만들어서 저장해두는 게 아니라, `next()` 호출마다 하나씩 계산해서 내놓는 객체. `print(reversed(value))`처럼 바로 찍으면 `<reversed object ...>`만 나옴 — `for`/`join()`/`list()`처럼 실제로 값을 꺼내는 동작이 있어야 진짜 값이 보임
- `range(len(value)-1, -1, -1)`의 `-1`(stop)은 `value[-1]` 같은 음수 인덱싱이 아니라 그냥 숫자 `-1`, "0까지 포함하고 멈춰라"는 경계선일 뿐

## 함수 기초 (`robot_game.py`, `function_with_param.py`)

- 함수는 `def 함수이름(파라미터):`로 정의, 반복되는 로직을 이름 붙여서 재사용하기 위해 씀
- **타입 힌트**(`country: str`): 파라미터가 어떤 타입인지 알려주는 힌트. 파이썬이 강제하진 않지만(다른 타입 넣어도 에러 안 남), IDE 자동완성/가독성에 도움됨
- **키워드 인자**(`함수(country="USA", name="Joon")`): 파라미터 이름을 명시해서 넘기면 **순서를 안 지켜도 됨**, 파라미터가 많아질수록 가독성 좋아짐
- **함수의 반환값**: 함수는 항상 한 가지 값만 반환할 필요 없음 — 입력값에 따라 다른 값을 반환하는 "블랙박스"로 생각하면 됨 (예: 이름이 비어있으면 에러 메시지, 아니면 정상 값 반환)

## 더치페이 계산 (`going_dutch.py`)

- `float(total) / num_of_people`처럼 `float()`으로 감싸는 건 **파이썬 3에서는 사실 불필요**함 — 파이썬 3의 `/`는 정수끼리 나눠도 항상 실수(float)를 반환하기 때문 (`62 / 3` → `20.666...`)
- 파이썬 2에서는 `/`가 정수끼리 나누면 소수점을 버렸어서(`62 / 3` → `20`) `float()` 변환이 필수였음 — 지금 코드에 남아있다면 그 시절 습관이거나, "이 값은 실수여야 한다"는 의도를 명시적으로 표현한 것

## 행맨 게임 (`hangman.py`)

- 리스트를 인덱스로 직접 수정(`lst[i] = char`)하며 정답 여부를 표시, `"_" not in lst`로 승리 조건 확인

## 언제 함수로 뽑아야 하는지 (`grading_program.py`)

- **가장 확실한 신호**: "이 로직이 값 하나를 넣으면 값 하나가 나오는, 독립된 작은 계산인가?" (예: 점수 하나 → 등급 하나)
- 같은 로직을 여러 번 반복해서 쓸 것 같거나, `for`문 안에 있어도 사실 반복 변수(`key` 등)와 상관없이 그 값 하나만으로 판단 가능한 로직이면 함수로 뽑을 수 있음
- `if score >= 90: elif score >= 80: ...`처럼 **더 큰/구체적인 조건부터 먼저** 체크해야 함 (FizzBuzz 조건 순서와 같은 원리)

## 소수 판별 함수 두 버전 (`prime_number.py`)

- 소수는 "1보다 큰 자연수" 중에서만 정의됨 → `if num <= 1: return False` 하나로 0/1/음수를 한 번에 걸러냄 (`range(2, num)`이 빈 범위가 되어 반복문을 그냥 통과해버리는 것을 방지)
- **버전 1 (`count` 방식)**: 나누어떨어지는 약수 개수를 끝까지 세고, `count > 0`이면 소수 아님 — 이미 나누어떨어짐을 찾았어도 끝까지 다 도는 비효율이 있음
- **버전 2 (`break` 방식)**: 나누어떨어지는 순간 `is_divisible = True`로 표시하고 `break`로 즉시 종료 — 더 효율적
- `is_` 로 시작하는 함수 이름은 관례상 `True`/`False`를 반환하는 함수를 뜻함 — `print()`만 하고 반환값이 없으면 이름과 실제 동작이 안 맞아서, 나중에 `if is_prime_number(n):`처럼 재사용하기 어려움
- `return print(...)`는 `print(...)` 실행 후 `print()`의 반환값(항상 `None`)을 그대로 반환하는 것과 같음 — 반환값 자체엔 의미 없고, "여기서 함수를 즉시 끝낸다"는 흐름 제어 역할만 함

## 다단계 중첩과 오버라이트 (`nesting.py`)

- **중첩(nesting)**: 리스트/딕셔너리 안에 또 다른 리스트/딕셔너리가 요소로 들어있는 것. 리스트 안에 딕셔너리(1단계), 그 리스트를 다시 리스트에 담으면(2, 3단계) 계속 깊어질 수 있음
- **오버라이트(overwrite)**: 이미 값이 있는 변수에 새 값을 다시 대입해서 이전 값을 덮어쓰는 것. 변수는 값을 담는 "상자"가 아니라 값을 가리키는 "이름표"라, 이름표를 다른 값으로 옮기면 이전 값과의 연결이 끊김 — 그 값을 가리키는 이름이 하나도 안 남으면 파이썬이 알아서 메모리에서 정리(가비지 컬렉션)함
  - 파이썬은 타입 체크를 안 하므로, 완전히 다른 구조(예: 1단계 중첩 → 3단계 중첩)로도 자유롭게 덮어쓸 수 있음
  - 단, 오버라이트된 변수(`countries`)가 예전 값을 잃는 것이지, 그 값을 구성했던 다른 변수들(`usa`, `south_korea`)은 각자의 이름으로 여전히 접근 가능

## 딕셔너리 (`dictionaries.py`)

| 문법 | 하는 일 |
|---|---|
| `dic[key]` | key로 값 조회 |
| `dic.items()` | key와 value를 **동시에** 꺼낼 때 (`for k, v in dic.items():`) |
| `for key in dic:` | 그냥 순회하면 key만 나옴, value는 `dic[key]`로 따로 접근 |
| `dic.keys()` / `dic.values()` | key/value만 모은 뷰(view) 반환, `list()`로 감싸면 일반 리스트로 보임 |
| `값 in dic` | 기본적으로 **key만** 검사함 (value는 검사 안 함) |

- `enumerate()`는 리스트/문자열처럼 순서가 있는 것에서 "인덱스+값"을 꺼낼 때 쓰는 것이라 딕셔너리의 "key+value" 쌍을 꺼내는 데는 안 맞음 — 딕셔너리는 `.items()`를 씀
- 딕셔너리의 key가 꼭 문자열일 필요는 없음 (`{1: 1, 2: 2}`처럼 숫자도 key로 가능)
