# 객체지향 프로그래밍 (oop)

## 클래스 기초 — Turtle 라이브러리 (`oop_turtle.py`)

- **클래스(class)**: 객체를 찍어내는 설계도. `Turtle`이 클래스
- **객체/인스턴스**: 클래스로 실제로 찍어낸 것. `john = Turtle()` → `john`이 `Turtle`의 인스턴스
- **메소드(method)**: 클래스 안에 정의돼서 특정 객체에 소속된 함수 (`john.forward(5)`, `john.shape("turtle")`). `객체.메소드()` 형태로 호출
- **함수(function)**: 특정 객체에 속하지 않는 독립적인 코드. `time.sleep()`은 메소드처럼 보이지만 사실 `time` 모듈 안의 함수 — `time`은 객체가 아니라 모듈이라 자기만의 상태가 없음
- **`from 모듈 import 이름`**: 모듈 전체가 아니라 그 안의 특정 이름 하나만 콕 집어 가져옴 (접두어 없이 바로 사용 가능). 그 이름이 클래스면, 클래스 안의 메소드들도 전부 같이 딸려옴 (메소드는 모듈이 아니라 클래스에 속한 것)
  - `import 모듈`(모듈 전체)은 여러 걸 폭넓게 쓸 때, `from 모듈 import 이름`은 딱 몇 개만 자주 쓸 때 편함

## 커스텀 클래스 & 생성자 (`custom_class.py`)

- **naming convention**: 클래스 이름은 PascalCase(`Car1`), 나머지(변수 등)는 snake_case가 파이썬(PEP8) 기본 스타일
- **동적 속성 추가**: `class Car1: pass`처럼 빈 클래스라도, 객체를 만든 뒤 `tesla.color = "red"`처럼 즉석에서 속성을 자유롭게 추가할 수 있음 (`vars(객체)`로 그 객체가 가진 속성들을 딕셔너리로 확인 가능)
- **생성자(constructor, `__init__`)**: 객체를 만드는 순간(`Car2(...)`) 자동으로 실행되는 함수. 매번 속성을 하나씩 즉석 추가하는 대신, 생성자에서 한 번에 정해두는 정석적인 방식
  - `__init__(self, color, engine_type)`의 `color`/`engine_type`은 그 함수 안에서만 쓰이는 매개변수(임시 값)
  - `self.color = color`는 "이 객체(`self`)의 `color` 속성에, 방금 받은 매개변수 값을 영구 저장"하는 것 — 왼쪽(`self.color`)과 오른쪽(`color`)은 이름이 같아 보여도 역할이 다름
- **다른 파일에서 클래스 가져오기**: `import car2`(모듈 전체, `car2.Car2(...)`로 접두어 필요) vs `from car2 import Car2`(그 이름만 콕 집어, 접두어 없이 `Car2(...)`) vs `from car2 import Car2 as c`(별명 지정, 이름이 길거나 겹칠 때 유용)

## 내장 자료형 — list/dict/set/tuple (`built_in_data_types.py`)

- **list**: mutable, `.append()`(맨 뒤 추가), `리스트[i] = 값`(인덱스로 변경 가능)
- **dict**: mutable, `딕셔너리[키] = 값`으로 추가와 변경을 둘 다 처리 — 그 키가 없으면 새로 추가, 있으면 값만 덮어씀 (문법은 동일). 한 키는 값을 하나만 가짐(여러 개 넣고 싶으면 값 자리에 리스트를 담아야 함). `append` 같은 메소드는 없음(순서 개념이 없어서)
- **set**: 중복을 없애고 싶을 때 사용. 원소 자체는 못 바꾸지만(unchangeable) `add()`/`remove()`로 추가·제거는 가능. 인덱스 접근 불가
  - `set((1, 2, 3))`처럼 이터러블을 넘겨 변환할 수도 있지만, 그냥 `{1, 2, 3}`(set 리터럴)로 쓰는 게 더 간결함 (ruff `C405` 경고 대상)
  - 빈 set은 `{}`(dict로 해석됨)가 아니라 `set()`으로 만들어야 함
- **tuple**: immutable, 인덱스 접근 가능, 생성 속도가 list보다 빠름. `list([])`/`dict({})`처럼 `tuple`도 자체 리터럴(`()`)이 있어서 `tuple()` 함수 호출이 필요 없음

## 상속 (Inheritance) & 오버라이딩 (`class_inheritance.py`)

- **상속**: `class 자식클래스(부모클래스):` 형태로 선언하면 부모 클래스의 속성/메소드를 물려받음
- **`super()`**: 부모 클래스를 가리키는 객체. `super().메소드()`로 부모의 메소드를 명시적으로 호출할 수 있음
  - `super().__init__()`을 안 부르면 부모의 `__init__`이 실행되지 않아서, 부모가 세팅하는 속성(`self.wheel_count` 등)이 자식 객체에 없음
- **오버라이딩(overriding)**: 부모에 있는 것과 **같은 이름의 메소드**를 자식이 다시 정의하는 것
- **메소드 탐색 순서**: `객체.메소드()`를 호출하면 파이썬은 `객체 → 객체의 클래스 → 부모 클래스` 순으로 찾다가, 처음 찾은 곳에서 멈춤
  - 자식이 같은 이름으로 재정의했으면 그 시점에 이미 찾아지므로, **부모 클래스까지는 아예 올라가지 않음** (자식 것이 부모 것을 가리는 셈)
  - 그래서 오버라이딩된 메소드를 호출하면 **항상 자식 버전만 실행**되고, 부모 버전은 `super()`로 명시적으로 부르지 않는 한 자동으로 같이 실행되지 않음
  ```python
  class Car:
      def start(self):
          print("started...")

  class ElectricCar(Car):
      def start(self):
          super().start()       # 있으면: started... 도 같이 출력됨
          print("No sound...")  # 없으면: No sound... 만 출력됨
  ```
- **`id()`**: 객체의 고유 식별값(메모리 주소 기반)을 반환. 속성 값 구성이 같아도 서로 다른 인스턴스면 `id()` 값은 다름 — 별개의 객체임을 확인하는 용도

## 고차함수 (Higher Order Function) & 데코레이터 (`high_order_function.py`)

- **함수가 일급 객체(first-class citizen)인 이유**: 객체 타입의 인스턴스이고, 변수에 저장 가능하고, 다른 함수의 파라미터로 전달 가능하고, 함수 안에서 반환 가능하고, 딕셔너리 같은 자료구조에 저장 가능함 — 이 5가지가 성립해서 고차함수가 가능함
- **`()`의 유무가 핵심**: `함수이름`(괄호 없음)은 "아직 실행 안 한 함수 자체", `함수이름()`(괄호 있음)은 "지금 실행해서 나온 결과값" — 함수를 변수에 저장하거나 다른 함수에 넘길 땐 괄호를 안 붙임
- **데코레이터(Decorator)**: 원본 코드를 바꾸지 않고 다른 함수를 감싸서 기능을 확장하는 것. `@데코레이터이름`을 함수 위에 붙이면 `그_함수 = 데코레이터이름(그_함수)`와 같은 뜻 — 바로 아래 함수가 자동으로 데코레이터 함수의 인자로 넘어감
  - 데코레이터 함수 안에서 `return inside`처럼 내부 함수를 괄호 없이 반환해야, 그 함수가 나중에 실제로 호출될 때(`sample_example()`) 실행됨
