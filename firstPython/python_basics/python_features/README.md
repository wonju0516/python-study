# 파이썬 기능 심화 (python_features)

## JSON 다루기 (`json_python.py`)

- **왜 `f.read()`만으로는 안 되냐**: `.txt`처럼 일반 텍스트는 글자 그대로 쓰면 되지만, JSON은 "구조화된 데이터(딕셔너리/리스트 모양)"라서 실제로 딕셔너리처럼 다루려면 변환이 한 단계 더 필요함. `f.read()`만 하면 그냥 문자열(str)이라 `data["key"]`처럼 접근 불가

| 함수                        | 하는 일                                                                     |
| --------------------------- | --------------------------------------------------------------------------- |
| `json.loads(문자열)`        | JSON 형식 **문자열**을 파이썬 `dict`/`list`로 변환 ("load string")          |
| `json.dumps(객체)`          | 파이썬 `dict`/`list`를 JSON 형식 **문자열**로 변환 ("dump string")          |
| `json.load(파일객체)`       | 파일을 직접 읽어서 바로 dict/list로 변환 (`f.read()` + `loads()`를 한 번에) |
| `json.dump(객체, 파일객체)` | dict/list를 바로 파일에 씀 (`dumps()` + `write()`를 한 번에)                |

- **`loads`/`dumps` vs `load`/`dump`**: 이름 끝에 `s`가 있으면 "문자열(string)"을 다루는 것, 없으면 "파일 객체"를 직접 다루는 것. 지금 코드는 `f.read()` + `json.loads()`를 따로 썼는데, `json.load(f)` 하나로 줄일 수도 있음

## datetime 다루기 (`datatime_python.py`)

- **`datetime.now()`**: 현재 시각을 datetime 객체로 반환. tz(시간대)를 안 넘기면 **naive datetime**(시간대 정보 없음) — 값 자체는 컴퓨터의 로컬 시간대 기준
- **`.year` / `.month` / `.day`**: 속성(property)이라 괄호 없이 접근. **`.weekday()`**는 메소드라서 괄호 필요 — 월요일=0 ~ 일요일=6으로 반환
- **`strptime(문자열, 포맷)`**: 문자열 → datetime 객체로 변환 ("parse time")
- **`strftime(포맷)`**: datetime 객체 → 원하는 형식의 문자열로 변환 ("format time")
- **자주 쓰는 포맷 코드**: `%Y`(4자리 연도), `%m`(월), `%d`(일), `%H`(시, 24시간), `%M`(분), `%S`(초)
- **`timedelta`**: 날짜/시간 간의 "차이"를 나타내는 객체. `datetime객체 + timedelta(days=1)`처럼 날짜 계산에 씀

## API 호출과 HTTP 상태 코드 (`api_python.py`)

- **API(Application Programming Interface)**: 서로 다른 두 프로그램이 대화할 수 있게 해주는 "중간 다리" 역할을 하는 소프트웨어. 앱 쓰기, 메시지 보내기, 날씨 확인 등 대부분의 활동 뒤에서 API 요청/응답이 일어남
- **`requests.get(url)`**: 그 url로 요청을 보내고 서버의 응답을 `response` 객체로 받음
- **`response.text`**: 응답 원본을 문자열로 (JSON이어도 아직 파싱 전, 그냥 문자열)
- **`response.json()`**: 응답이 JSON 형식일 때, 그 텍스트를 파이썬 `dict`/`list`로 파싱해서 바로 돌려줌 (`json.loads(response.text)`와 같은 역할)
- **`response.status_code`**: 요청이 어떻게 처리됐는지 알려주는 숫자
- **`response.raise_for_status()`**: status_code가 에러 범위(4xx/5xx)면 자동으로 에러를 발생시켜주는 메소드

### HTTP 상태 코드 분류

| 범위 | 의미                                              |
| ---- | ------------------------------------------------- |
| 1xx  | Informational responses — 처리 중이라는 안내      |
| 2xx  | Successful responses — 요청 성공                  |
| 3xx  | Redirection messages — 다른 곳으로 리다이렉트     |
| 4xx  | Client error responses — 요청(클라이언트) 쪽 잘못 |
| 5xx  | Server error responses — 서버 쪽 잘못             |

### 자주 보는 상태 코드

- **200 OK**: 요청 성공. "성공"의 구체적 의미는 어떤 HTTP 메서드였는지에 따라 달라짐
- **403 Forbidden**: 그 콘텐츠에 접근 권한이 없음. 신원(로그인 등)은 알고 있지만 권한이 없어서 거부하는 것 (401 Unauthorized와 달리 "누군지는 앎")
- **404 Not Found**: 서버가 요청한 리소스를 찾을 수 없음. API에서는 URL 자체는 유효한데 그 리소스가 존재하지 않는다는 뜻일 수도 있음 — 권한 없는 클라이언트에게 403 대신 404를 보내서 "그런 리소스가 있는지 없는지조차" 숨기는 용도로도 쓰임
- **503 Service Unavailable**: 서버가 지금 요청을 처리할 준비가 안 됨. 보통 서버 점검/과부하 상황. 클라이언트에게 친절한 안내 메시지와, 가능하면 `Retry-After` 헤더(언제 다시 시도하면 될지)를 같이 보내는 게 권장됨. 이 응답은 캐시하면 안 됨(일시적 상태라서)
- **504 Gateway Timeout**: 서버가 게이트웨이/프록시 역할을 하고 있는데, 그 뒤(upstream) 서버로부터 제시간에 응답을 못 받았을 때 발생

## 클래스 메소드, static 메소드 (`python_method.py`)

- **클래스 메소드는 호출될 때, 객체 인스턴스가 아니라 클래스 자체를 가리키는 `cls`라는 파라미터를 받는다**
- **클래스 메소드는 `cls`밖에 없어서 객체 인스턴스의 상태(instance state)는 바꿀 수 없다** — 그건 `self`가 있어야 가능한 일. **다만 그 클래스의 모든 인스턴스에 공통으로 적용되는 클래스 상태(class state)는 바꿀 수 있다**
- **인스턴스 상태 vs 클래스 상태**: `self.속성`(예: `self.body_type`)은 객체마다 따로 갖는 값(인스턴스 상태). 클래스 변수(예: `Car.total_count`처럼 클래스에 직접 붙은 값)는 모든 인스턴스가 공유하는 값(클래스 상태) — `cls.클래스변수 = 값`으로 클래스 메소드 안에서 바꿀 수 있음
- **`cls(...)`로 새 객체 만들기(팩토리 메소드)**: `cls("sedan")`은 `Car("sedan")`과 같은 뜻. 정해진 값으로 미리 세팅된 객체를 만들어주는 대안 생성자 패턴
- **`__repr__`**: 객체를 `print()`할 때 어떤 문자열로 보여줄지 정하는 매직 메소드. 없으면 `<__main__.Car object at 0x...>` 같은 기본값이 찍힘

### static 메소드 (`@staticmethod`)

- **static 메소드는 `self`도 `cls`도 안 받는 메소드다.** 클래스에 소속돼 있을 뿐, 객체나 클래스 자체와 연결돼있지 않음
- 그래서 **객체를 만들지 않고도** `클래스명.메소드()`로 바로 호출 가능
- `self`가 없어서 **어떤 객체의 상태도 읽거나 바꿀 수 없음** — "그 클래스와 관련은 있지만 특정 객체 상태와는 무관한 독립적인 계산"을 넣어두는 용도

### 메소드 종류 비교

| 종류            | 데코레이터      | 첫 파라미터 | 호출 방식                              | 할 수 있는 것                         |
| --------------- | --------------- | ----------- | -------------------------------------- | ------------------------------------- |
| 인스턴스 메소드 | (없음)          | `self`      | `객체.메소드()`                        | 그 객체의 상태(`self.속성`) 읽기/변경 |
| 클래스 메소드   | `@classmethod`  | `cls`       | `클래스.메소드()` 또는 `객체.메소드()` | 클래스 전체가 공유하는 상태 읽기/변경 |
| static 메소드   | `@staticmethod` | 없음        | `클래스.메소드()`                      | 아무 상태도 못 건드림, 그냥 계산만    |

## 타입 힌트 (`typing.py`)

- **`변수명: 타입 = 값`**: 타입 힌트(annotation). "이 변수는 이 타입이어야 한다"는 표시일 뿐, 파이썬이 강제로 검사하지 않음 — 다른 타입 값을 넣어도 실행 시점에는 에러가 안 남
- **`def 함수(파라미터: 타입) -> 반환타입:`**: `->`는 함수가 반환할 값의 타입을 표시하는 문법 (파라미터 타입은 `:`, 반환 타입은 `->`로 구분)
- **캐스팅(casting)과의 차이**: 타입 힌트는 "이래야 한다"는 참고 표시일 뿐이고, `int(3.5)`처럼 실제로 값의 타입을 바꾸는 동작은 캐스팅(형변환)이라 부름 — 서로 다른 개념
- **에디터의 역할**: 파이썬 자체는 힌트와 다른 타입을 넣어도 신경 안 쓰지만, VS Code(Pylance)는 타입 검사 기능(`python.analysis.typeCheckingMode`)을 켜두면 힌트와 실제 값이 안 맞을 때 에디터에서 경고를 띄워줌 — 실행을 막는 건 아니고, 미리 알려주는 역할

## 스페셜(던더) 메소드 (`special_method.py`)

- **던더(dunder) 메소드**: 이름이 `__xxx__` 형태인 메소드. 직접 호출하지 않아도 `print()`, `len()`, `==` 같은 파이썬 기본 문법/함수를 만났을 때 파이썬이 알아서 호출해줌
- 정의하지 않으면 파이썬 기본 동작(또는 에러)을 따르고, 정의하면 그 클래스만의 동작으로 오버라이드됨
- **`__del__`과 가비지 컬렉션은 다른 개념**: 객체를 가리키는 참조가 하나도 안 남아 참조 카운트가 0이 되는 순간 CPython이 즉시 `__del__`을 호출함 (참조 카운팅). 스크립트가 끝나면서 전역 변수의 참조가 정리돼도 같은 방식으로 호출됨 — `gc` 모듈이 담당하는 순환 참조 정리(가비지 컬렉션)와는 별개의 메커니즘

### 현업에서 자주 쓰는 던더 메소드

| 카테고리        | 트리거 상황                | 대표 메소드                                              |
| --------------- | --------------------------- | --------------------------------------------------------- |
| 생성/소멸       | 객체 생성/삭제 시점         | `__init__`, `__new__`, `__del__`                          |
| 문자열 표현     | `print()`, `repr()`         | `__str__`, `__repr__`                                     |
| 비교 연산       | `==`, `<`, `>` 등           | `__eq__`, `__lt__`, `__gt__`, `__le__`, `__ge__`           |
| 산술 연산       | `+`, `-`, `*`, `/`          | `__add__`, `__sub__`, `__mul__`, `__truediv__`             |
| 컨테이너 흉내   | `len()`, `obj[i]`, `in`     | `__len__`, `__getitem__`, `__setitem__`, `__contains__`   |
| 반복            | `for x in obj`              | `__iter__`, `__next__`                                    |
| 호출 가능하게   | `obj()` 처럼 함수처럼 호출  | `__call__`                                                 |
| 컨텍스트 매니저 | `with obj:`                 | `__enter__`, `__exit__`                                   |
| 불리언 판정     | `if obj:`                   | `__bool__`                                                 |

- **실무에서 특히 자주 쓰는 것**: `__init__`, `__repr__`(디버깅용 표현), `__eq__`, `__len__`, `__iter__`. `__str__`은 사용자에게 보여줄 표현, `__repr__`은 개발자가 디버깅할 때 보는 표현 — 보통 `__repr__`은 항상 정의하고 `__str__`은 필요할 때만 따로 정의함
- `__add__`류 산술 연산자나 `__enter__`/`__exit__`(with문)은 벡터/행렬 클래스, 파일·DB 연결 관리 등 커스텀 자료구조나 리소스 관리 클래스를 만들 때 주로 씀

## `__name__` (`__name__1.py`, `__name__2.py`)

- **`__name__`**: 모든 모듈(`.py` 파일)이 자동으로 갖는 내장 변수. 그 파일이 **직접 실행**됐으면 값이 `"__main__"`, **다른 파일에서 `import`**됐으면 값이 그 파일의 모듈명(파일명)이 됨
- **`if __name__ == "__main__":`**: "이 파일이 직접 실행됐을 때만" 실행하고 싶은 코드(테스트/예제 실행문)를 감싸는 관용구. 이 가드가 없으면 다른 파일이 이 파일을 `import`만 해도 안에 있는 테스트 코드가 같이 실행돼버림
- **동작 확인**: `__name__2.py`가 `import __name__1`을 하면 그 순간 `__name__1.py`의 코드가 통째로 실행되는데, 이때 `__name__1`의 `__name__`은 `"__main__"`이 아니라 `"__name__1"`이라 `else` 분기를 탐. `__name__2.py` 자신은 직접 실행이라 `if` 분기를 탐
- 하나의 `.py` 파일이 "재사용 가능한 모듈"과 "직접 실행 가능한 스크립트" 역할을 동시에 깔끔하게 할 수 있게 해주는 패턴

## 제너레이터(Generator)와 이터레이터(Iterator) (`generators.py`)

- **제너레이터 함수**: `return` 대신 **`yield`**를 쓰는 함수. 호출해도 코드가 바로 실행되지 않고 "제너레이터 객체"만 만들어짐(아직 아무 계산도 안 한 상태, lazy)
- **`yield`**: 그 지점에서 값을 하나 내보내고 함수 실행을 잠깐 멈춤. `return`처럼 함수가 완전히 끝나는 게 아니라, 다음 요청이 오면 멈췄던 자리부터 이어서 실행
- **리스트 vs 제너레이터**: 리스트는 결과를 전부 미리 계산해서 한 번에 메모리에 쌓아두지만, 제너레이터는 요청받을 때마다(`next()` 호출마다) 그때그때 하나씩만 계산 — 데이터가 크거나 끝이 없는 경우 메모리 절약에 유리
- **이터레이터(iterator)**: `next()`를 호출할 때마다 값을 하나씩 꺼내주는 객체(어디까지 꺼냈는지 상태를 기억함). 제너레이터는 이 이터레이터를 `__iter__`/`__next__`를 직접 구현하지 않고도 쉽게 만들 수 있는 방법
- **iterable(순회 가능) ≠ iterator**: `list`, `tuple`, `str`, `dict`, `set`은 모두 `for`문으로 순회 가능한 iterable이지만, 그 자체로는 iterator가 아니라서 `next()`를 바로 쓰면 `TypeError`가 남 (예: `next("Joon")` → `'str' object is not an iterator`). `iter(객체)`로 먼저 변환해야 `next()`를 쓸 수 있음
- **`for`문과의 관계**: `for x in 제너레이터:`는 내부적으로 `next()`를 자동으로 계속 호출해주는 것 — 직접 `next()`를 안 불러도 됨

## map / filter (`map_filter.py`)

| 함수 | 하는 일 | 반환값 |
|---|---|---|
| `map(함수, 리스트)` | 리스트의 각 원소에 함수를 하나씩 적용해서 새 결과를 만듦 | map 객체 (제너레이터 비슷, 즉시 리스트 아님) |
| `filter(함수, 리스트)` | 함수 결과가 `True`인 원소만 걸러서 남김 (함수는 반드시 bool 반환) | filter 객체 |

- `map`/`filter` 둘 다 결과를 바로 리스트로 안 주고 각각 고유한 객체를 반환함 — `print()`해도 값이 안 보이고, `for`문으로 하나씩 꺼내거나 `list()`로 감싸야 실제 값을 확인 가능
- `map(함수, 리스트1, 리스트2)`처럼 리스트를 여러 개 넘기면, 같은 순서끼리 짝지어서 함수에 인자를 여러 개 넘겨줄 수 있음
- `filter`에 넘기는 함수는 `True`/`False`를 반환해야 하고, 그 결과가 `True`인 원소만 살아남음

## 람다(lambda) 표현식 (`lambda_function.py`)

- **람다**: 이름 없이 한 줄로 만드는 간단한 함수. 문법: `lambda 인자: 표현식` → `return` 없이 그 표현식의 결과가 바로 반환값이 됨
- `square = lambda num: num**2`처럼 변수에 담아 이름 붙여 쓸 수도 있지만, 진짜 쓰임새는 **`map`/`filter`처럼 "함수 자체를 인자로 넘겨야" 하는 상황**에서 `def`로 따로 이름 붙이기 귀찮은 한 줄짜리 함수를 그 자리에서 즉석으로 만들어 넘기는 것
- `list(map(lambda num: num**2, number_list))`, `list(filter(lambda num: num % 2 == 0, number_list))`처럼 `map`/`filter`와 짝지어 쓰는 게 가장 흔한 패턴

## collections 모듈 (`collections_python.py`)

- **collections 모듈**: `list`/`dict`/`tuple`/`set` 기본 컬렉션만으로 부족한 상황을 위한 특화된 컬렉션 타입 모음
- ! **주의**: 이 모듈과 이름이 겹치는 `collections.py` 같은 파일명을 쓰면, 그 폴더 안에서 `from collections import ...` 했을 때 표준 라이브러리 대신 자기 자신을 불러오는 충돌이 생김 (`array.py`와 같은 문제) — 그래서 파일명을 `collections_python.py`로 지음

### Counter — 등장 횟수 세기

- 리스트/문자열 안의 각 원소가 몇 번 나오는지 자동으로 세어주는 딕셔너리 (`dict`를 상속)
- `Counter(리스트)` / `Counter(문자열)` / `Counter(단어리스트)` 등 순회 가능한 것이면 뭐든 넣을 수 있음
- 출력 순서는 삽입 순서가 아니라 **등장 횟수 내림차순**
- `most_common()`: `(원소, 횟수)` 튜플로 짝지어서, 횟수 많은 순서대로 담은 **리스트**를 반환 — 튜플 리스트를 순회할 땐 `for 원소, 횟수 in c.most_common():`처럼 바로 언패킹 가능

### defaultdict — 없는 key여도 에러 안 남

- 일반 `dict`는 없는 key에 접근하면 `KeyError` 발생. `defaultdict(팩토리함수)`는 없는 key에 접근하는 순간 그 팩토리 함수를 **인자 없이 호출**한 결과를 자동으로 채워 넣어줌
- `defaultdict(lambda: 0)`처럼 직접 람다로 써도 되고, `defaultdict(int)`(결과 0), `defaultdict(list)`(결과 `[]`)처럼 내장 타입을 그대로 넘기는 것도 흔한 패턴
- `dd["없는키"]`처럼 그냥 **읽기만 해도** 그 순간 key가 자동 생성된다는 점이 일반 dict와 다름

### namedtuple — 이름으로도 접근되는 튜플

- 일반 튜플은 인덱스로만 접근 가능해서(`t[1]`) 값이 뭘 의미하는지 코드만 봐선 알기 어려움
- `namedtuple("타입이름", [필드명, ...])`: 지정한 필드를 가진 새로운 튜플 **타입**을 만들어 반환 (`int`, `str`처럼 새 자료형이 하나 생기는 것)
- `namedtuple("Dog", ...)`처럼 넘기는 문자열은 "타입 내부에 저장되는 이름"이고, `Dog = namedtuple(...)`의 `Dog`는 그 결과를 담는 "변수 이름" — 서로 다른 자리라 이론상 다르게 지어도 되지만, 관례상 항상 똑같이 맞춰서 씀
- 만들어진 타입으로 인스턴스를 찍어내면(`Dog(age=5, ...)`), 여전히 튜플이라 인덱스(`[0]`)로도, 이름(`.age`)으로도 둘 다 접근 가능

### deque — 양쪽 끝 다 빠른 큐

- "Double-Ended Queue"의 줄임말, **"덱"**이라고 읽음(데큐 아님). 이름처럼 양쪽 끝(앞/뒤) 모두에서 추가/삭제가 O(1)
- 일반 `list`는 맨 뒤 추가/삭제만 O(1)이고 맨 앞은 나머지가 다 밀려서 O(n) — 앞쪽도 자주 건드릴 땐 `list`보다 `deque`가 유리
- 메소드 4개: `append()`(뒤에 추가) / `appendleft()`(앞에 추가) / `pop()`(뒤에서 제거) / `popleft()`(앞에서 제거)
- `deque`는 FIFO(큐)를 강제하는 자료구조가 아니라 **양쪽 다 자유롭게 쓸 수 있는 범용 구조** — `append`+`popleft` 조합이면 큐(FIFO)처럼, `append`+`pop` 조합이면 스택(LIFO)처럼 동작
- **`maxlen` 옵션**: 꽉 찬 상태에서 새 값이 들어오면 **"방금 넣은 쪽의 반대쪽" 값이 자동으로 밀려남**. `append()`로 넣었다면 왼쪽이, `appendleft()`로 넣었다면 오른쪽이 밀림 — "먼저 들어온 값이 나간다(FIFO)"가 아니라 "삽입한 반대쪽이 밀린다"가 정확한 규칙이고, 계속 `append()`만 쓰는 경우에 한해 결과적으로 FIFO처럼 보이는 것뿐

## zip 압축/해제 — zipfile, shutil (`zip.py`)

### `open()`의 `"w+"` 모드

- `"w"`처럼 없으면 새로 만들고 있으면 덮어쓰되, 같은 파일 객체로 **쓰기+읽기 둘 다 가능**한 모드

### `zipfile` — 파일을 하나씩 골라 압축

- **`zipfile.ZipFile(경로, "w")`**: `open()`처럼 "zip 파일을 다루는 객체"를 만듦. `"w"`는 새 압축 상자를 만드는 모드, `"r"`은 이미 있는 zip을 읽는 모드
- **`.write(파일, arcname=..., compress_type=...)`**: 그 상자 안에 파일 하나를 압축해서 담음
  - `compress_type`: 압축 방식. `ZIP_DEFLATED`(용량 실제로 줄이는 진짜 압축) vs 기본값 `ZIP_STORED`(압축 아니고 그냥 담기만 함, 용량 그대로)
  - `arcname`: zip **안에서** 쓸 이름/경로. **생략하면 실제 파일의 전체 경로가 그대로 zip 내부 폴더 구조로 저장돼버림** — 항상 `arcname="파일명"`처럼 짧게 지정할 것
- **`.close()`**: 상자 뚜껑 닫기 — 저장 마무리
- **`.extractall(폴더)`**: 상자 안 파일들을 전부 압축 해제해서 그 폴더에 풀어놓음

```python
comp_file = zipfile.ZipFile(BASE_DIR / "comp.zip", "w")
comp_file.write(BASE_DIR / "readme1.txt", arcname="readme1.txt", compress_type=zipfile.ZIP_DEFLATED)
comp_file.close()

zip_obj = zipfile.ZipFile(BASE_DIR / "comp.zip", "r")
zip_obj.extractall(BASE_DIR / "extracted")
```

### `shutil` — 폴더 통째로 압축

- **`shutil`("shell utilities")**: zip 말고도 파일 복사/이동/삭제 등 파일 시스템 작업을 폭넓게 다루는 표준 라이브러리
- **`shutil.make_archive(결과이름, 형식, 압축할폴더)`**: 지정한 폴더를 통째로 압축 — `zipfile`처럼 파일을 하나씩 안 골라도 됨. 폴더 기준 상대 경로로 저장되므로 `zipfile.write()`와 달리 `arcname` 문제가 없음
  - 두 번째 인자(`"zip"`)는 **결과물을 어떤 형식으로 만들지**(출력 형식)
- **`shutil.unpack_archive(zip경로, 풀위치, 형식)`**: 압축 해제
  - 세 번째 인자(`"zip"`)는 **지금 주는 이 파일이 무슨 형식인지**(입력 형식) — 생략하면 확장자로 자동 추측하지만, 명시하면 더 안전하고 명확함. `make_archive`와 인자 순서가 다르니(형식이 2번째 vs 3번째) 주의

```python
shutil.make_archive(BASE_DIR / "folder_zip", "zip", BASE_DIR / "zipme")
shutil.unpack_archive(f"{BASE_DIR / 'folder_zip'}.zip", BASE_DIR / "extracted2", "zip")
```

- ! **주의**: `dir_to_zip`을 프로젝트 폴더 전체(`BASE_DIR`)로 지정하면, 그 폴더 안의 `.py` 파일들까지 전부 압축돼버림 — 압축 대상은 전용 폴더(예: `zipme/`)로 따로 분리하는 게 안전함

## SMTP로 이메일 보내기 (`smtp_python.py`)

- **SMTP(Simple Mail Transfer Protocol)**: 이메일을 보낼 때 쓰는 표준 프로토콜. `smtplib`은 파이썬에서 이 프로토콜로 이메일을 코드로 직접 보낼 수 있게 해주는 표준 라이브러리
- **주요 흐름**: `smtplib.SMTP(서버주소, 포트)`로 서버에 연결 → `starttls()`로 통신 암호화 → `login()`으로 로그인 → `sendmail()`로 발송
- **포트 587**: STARTTLS 방식으로 메일 보낼 때 쓰는 표준 포트 (서버 주소와는 별개 — 서버 주소는 "어느 회사 서버인지", 포트는 "그 서버의 어떤 창구를 쓸지")
- **앱 비밀번호(App Password)**: 요즘 대부분의 이메일 서비스는 보안 때문에 평소 로그인 비밀번호로는 이 방식이 안 통함. 계정 보안 설정에서 이 코드 전용으로 따로 발급받는 비밀번호를 써야 함
- ! **주의**: 이메일 계정/비밀번호처럼 실제 개인정보가 들어간 코드는 git에 커밋하면 안 됨
