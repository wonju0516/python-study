# 자료구조 (Data Structure)

## 리스트 (List) — 추상 데이터 타입 vs 파이썬 구현

- **추상 데이터 타입(ADT)으로서의 리스트**: "순서가 있고, 인덱스로 접근/삽입/삭제가 가능하다"는 개념적 설계도일 뿐, 내부 구현 방식은 정해져 있지 않음
  - 배열(Array) 기반으로 구현 가능: 인덱스 접근 빠름 O(1), 중간 삽입/삭제 느림 O(n)
  - 연결 리스트(Linked List) 기반으로 구현 가능: 중간 삽입/삭제 빠름 O(1), 인덱스 접근 느림 O(n)
- **파이썬의 `list`**: 이 ADT를 실제로 구현한 결과물. 내부적으로 **동적 배열(dynamic array)** 방식이라, 인덱스 접근이 빠르고(O(1)), 여러 타입을 섞어 담을 수 있으며(이질적), 크기도 자동으로 늘어남(가변 길이)

```python
mixed = [1, "two", 3.0]   # * 타입 섞어서 담기 가능
print(mixed[1])            # * 인덱스로 O(1) 접근 -> "two"
```

## 정적 배열 vs 동적 배열

- **정적 배열**: 생성할 때 크기를 고정해야 하고 이후 못 바꿈 (예: C의 `int arr[5]`)
- **동적 배열**: 크기가 꽉 차면 더 큰 메모리 공간을 자동으로 잡고 기존 데이터를 복사해서 옮김. 파이썬 `list`가 이 방식
- 참고: `array` 모듈은 파이썬에서 제공하는 진짜 "동질적(한 타입만)" 배열. 문자열은 담을 수 없고 숫자 타입(`"i"`=정수, `"f"`=단정도 실수, `"d"`=배정도 실수)만 가능. **주의: 파일 이름을 `array.py`로 지으면 `import array` 시 표준 라이브러리 대신 자기 자신을 불러오는 충돌이 발생하므로 피해야 함**

```python
from array import array
nums = array("i", [1, 2, 3])  # * "i" = 정수만 담는 배열 -> 문자열 넣으면 TypeError
```

## 선형 vs 비선형 자료구조

- **선형(Linear)**: 데이터가 한 줄로 순서대로 이어짐 — 배열, 리스트, 스택, 큐, 연결 리스트
- **비선형(Non-linear)**: 데이터가 여러 갈래로 뻗어나가거나 얽혀있음 — 트리, 그래프, 힙

## 리스트에 값 채워 넣는 방법 (append / insert / 인덱스 대입)

- `append(값)` / `insert(인덱스, 값)` → 리스트 **크기를 늘리면서** 새 값을 넣음
  - `append`는 맨 뒤에 추가, `insert`는 원하는 인덱스에 끼워넣기(그 자리 값은 뒤로 밀림)
- `리스트[인덱스] = 값` → 크기는 그대로 두고, **이미 있는 그 자리 값을 덮어쓰는 것(대입)**
  - 대입은 그 인덱스가 이미 존재할 때만 가능. 빈 리스트에 `evens_list[0] = 1`처럼 쓰면 `IndexError` 발생
  - 따라서 빈 리스트를 채워나갈 땐 `append`/`insert`를 써야 하고, 이미 채워진 자리 값만 바꿀 땐 인덱스 대입을 사용

## 배열 요소 삽입 시 인덱스가 흔들리는 문제 → 딕셔너리

배열(리스트) 중간에 값을 끼워 넣으면 그 뒤 요소들의 인덱스가 전부 한 칸씩 밀림.
```python
arr = ["a", "b", "c"]
arr.insert(1, "X")  # ["a", "X", "b", "c"] -> "b"가 인덱스 1 -> 2로 밀림
```
특정 값의 "자리(키)"를 고정해서 유지하고 싶다면 딕셔너리(`dict`)가 더 적합함 — key-value 짝은 다른 항목이 추가/삭제돼도 움직이지 않음.

## 0 옮기기 (배열을 순서 유지하며 in-place로 재배치)

리스트에서 0을 모두 찾아 뒤로 보내고, 나머지 요소는 원래 순서를 유지하는 문제. 새 리스트를 만들지 않고 원본 안에서 값 위치만 바꾸는(in-place) 방식.

- **한 번의 루프로 처리(투 포인터)**: `index`(읽는 포인터)와 `zero_index`(0 아닌 값을 써야 할 자리)를 같이 옮기며, 둘이 달라졌을 때만(=이미 0을 지나쳤을 때만) 원래 자리를 0으로 비움
- **두 단계로 나눠 처리(더 직관적)**: 1단계에서 0 아닌 값들을 앞으로 눌러 담고, 2단계에서 남은 뒤쪽 칸을 전부 0으로 채움
- 두 방식 모두 시간복잡도 O(n), 공간복잡도 O(1)로 동일 (루프 횟수 차이는 상수 배수라 Big-O상 무의미)
- 참고: `0`은 짝수임 (`0 % 2 == 0`)

## 리스트 결합 — zip

```python
list(zip(movie_list, ratings_list))  # 두 리스트를 튜플 쌍으로 묶은 리스트로 변환
```
`zip`은 하나 이상의 이터러블을 받아 요소를 순서대로 묶은 zip 객체를 반환하며, `list()`로 감싸 리스트로 변환해서 사용.

## set — 중복 없는 값들의 집합

- 중복을 허용하지 않고 순서가 보장되지 않는 자료구조
- `in` 연산이 리스트보다 빠름(평균 O(1) vs 리스트 O(n)) → 중복 확인, 존재 여부 확인에 적합
- 집합 연산 가능: `a & b`(교집합), `a | b`(합집합), `a - b`(차집합), `.intersection()`(2개 이상 세트도 가능: `s1.intersection(s2, s3, s4)`)

```python
a, b = {1, 2, 3}, {2, 3, 4}
print(a & b)   # {2, 3}       -> 교집합
print(a | b)   # {1, 2, 3, 4} -> 합집합
print(a - b)   # {1}          -> 차집합
```

## 리스트 축약(List Comprehension)으로 교집합 구하기

```python
[v for v in list1 if v in list2]
```
`list1`을 돌면서(`for v in list1`), `list2`에도 있는 값만 골라서(`if v in list2`) 새 리스트에 담음 → 두 리스트의 교집합. `set`의 `intersection()`을 쓰면 중복 제거까지 되면서 더 빠르게 구할 수도 있음.

## 클래스(class) 기초 — `__init__` / `self` / `__str__`

- `__init__(self, ...)`: 객체(인스턴스)를 만들 때 초기 데이터를 설정하고 속성을 부여하기 위해 사용, 객체 생성 시점에 자동 실행
- `self`: 지금 만들어지는(다뤄지는) 그 객체 자기 자신을 가리키는 참조
- `__str__(self)`: 객체를 사람이 읽기 좋은 문자열로 표현하기 위해 사용, `print()`/`str()` 호출 시점에 자동 실행 (없으면 `<__main__.클래스이름 object at 0x...>`가 기본 출력됨)

```python
class Dog:
    def __init__(self, name):
        self.name = name        # * self = 지금 만들어지는 이 객체 자신

    def __str__(self):
        return f"멍멍이 {self.name}"

print(Dog("초코"))  # 멍멍이 초코 -> print()가 자동으로 __str__ 호출
```

## 연결 리스트 (Linked List)

- **노드(Node)**: 값(`data`)과 다음 노드를 가리키는 포인터(`next`)로 이루어진 단위. 노드들을 `next`로 줄줄이 이어붙인 것이 "노드의 체인"
- **head / tail**: head는 첫 번째 노드를 가리키는 참조, tail은 마지막 노드(그 노드의 `next`가 `None`)
- 배열과 달리 인덱스가 없어서 **임의 접근(random access)이 불가능** — 원하는 위치로 바로 점프 못 하고, head부터 `next`를 하나씩 따라가야만 함(O(n))
- 대신 삽입/삭제 시 다른 요소를 밀어낼 필요 없이 **포인터 2개만 바꾸면 됨**(O(1))
- 종류: 단일(다음 포인터만) / 이중(다음+이전 포인터) / 환형(마지막 노드가 첫 노드를 다시 가리킴)
- 시간복잡도: 접근·탐색 O(n) vs 삽입·삭제 O(1)

| 메서드 | 하는 일 |
|---|---|
| `append(data)` | 맨 뒤에 새 노드 추가. head 없으면 새 노드를 head로, 있으면 tail까지 이동 후 연결 |
| `search(target)` | head부터 순회하며 값이 있는지 확인 |
| `remove(target)` | 대상이 head면 head를 다음 노드로 교체, 아니면 `previous`/`current` 두 포인터로 순회하며 찾으면 `previous.next = current.next`로 건너뛰게 연결 (찾자마자 `return` 안 하면 중복값일 때 여러 개 지워지는 버그 생김) |
| `reverse_list()` | `previous`/`current`/`next` 세 포인터로 각 노드의 화살표 방향을 반대로 뒤집음, 마지막엔 `previous`가 새 head (끝나는 시점엔 `current`가 `None`이라 `previous`를 써야 함) |
| `detect_cycle()` | 토끼와 거북이 알고리즘: `slow`(한 칸), `fast`(두 칸)를 동시에 이동시켜 둘이 같은 노드(`is`로 비교, 값이 아니라 객체 자체가 같은지)에서 만나면 사이클 있음. `try`/`except AttributeError`로 "끝(`None`)까지 갔다"를 사이클 없음으로 처리 |

**`collections.deque`**: 파이썬 내장 자료구조로, 내부가 연결 리스트 방식이라 양쪽 끝(`append`/`appendleft`, `pop`/`popleft`) 모두 O(1). 이미 `__str__`이 구현돼있어 `print(d)`만 해도 내용이 보임(직접 만든 클래스와 다른 점). `maxlen`을 지정하면 꽉 찼을 때 오래된 값이 자동으로 밀려나 원형 큐와 비슷하게 동작.

## 스택 (Stack)

- **ADT**: "넣은 순서의 역순으로 꺼낸다"(LIFO, Last In First Out)는 규칙만 정의. push/pop 둘 다 O(1)이어야 함
- **배열로 구현**: 배열은 맨 뒤 추가/삭제가 O(1)이라 **뒤(tail)를 top으로 사용**(`append`/`pop`). 앞에 넣으면 나머지가 전부 밀려서 O(n)
- **연결 리스트로 구현**: head만 갖고 있으면 뒤(tail) 삭제는 이전 노드를 못 찾아 무조건 O(n)(단일 연결리스트는 `prev`가 없음). push는 tail 포인터를 따로 두면 O(1)로도 가능하지만, pop이 tail에서 절대 O(1)이 안 되므로 push도 pop과 같은 쪽(head)에 맞춤
- **실전 코딩테스트에서는** 클래스 없이 그냥 파이썬 `list`를 스택처럼 씀: `append()`(push), `pop()`(pop), `list[-1]`(peek), `not list`(is_empty) — `Stack`/`Node` 클래스 구현은 원리 학습용

```python
stack = []
stack.append(1)   # * push
stack.append(2)
print(stack.pop())  # 2 -> 나중에 넣은 게 먼저 나옴(LIFO)
```

| 문제 | 핵심 아이디어 |
|---|---|
| 문자열 뒤집기 | 한 글자씩 push한 뒤 전부 pop하면, 나중에 넣은(마지막) 글자부터 나와서 자연히 뒤집힌 순서가 됨. 단, `[::-1]`이나 `"".join(reversed(s))`가 훨씬 간단함 |
| 최소/최대 스택 (MinStack/MaxStack) | 메인 스택과 별도로, **매 push 시점마다 "그때까지의 최솟값/최댓값"을 그대로 같이 기록해두는 보조 스택**을 둠. 보조 스택은 "최솟값만 압축해서 저장"하는 게 아니라 메인 스택과 항상 같은 개수(높이)를 유지 — 개수가 어긋나면 pop할 때 서로 다른 시점끼리 짝지어져 값이 틀어짐. `get_min()`/`get_max()`는 보조 스택의 맨 위만 보면 되어 O(1) |
| 괄호 짝 검사 | 여는 괄호(`(`,`{`,`[`)는 push, 닫는 괄호를 만나면 스택이 비어있는지(짝 없음) 먼저 확인하고, `pop()`한 값이 딕셔너리(`{"닫는 괄호": "여는 괄호"}`)로 찾은 짝과 같은지 비교. 끝까지 다 돌고 스택이 안 비어있으면(안 닫힌 여는 괄호가 남음) 실패. "이 값이 오면 항상 정해진 저 값과 대응"하는 관계가 여러 개 반복되면 `if`/`elif`를 나열하는 대신 딕셔너리로 묶을 수 있다는 신호 |

자세한 예제는 [stack_file.py](stack_file.py) 참고.

## 큐 (Queue)

- **ADT**: "넣은 순서대로 꺼낸다"(FIFO, First In First Out). enqueue(뒤에 추가)/dequeue(앞에서 제거) 둘 다 O(1)이어야 함
- **연결 리스트로 구현**: `front`(꺼낼 위치)와 `rear`(넣을 위치)를 각각 따로 들고 있어야 양쪽 끝 모두 O(1) 가능. `front`만 있으면 뒤에 추가할 때마다 끝까지 순회해야 해서 O(n)
  - `enqueue`: 새 노드를 만들어 `rear.next`로 연결한 뒤, `rear` 이름표를 새 노드로 옮김 — 옮겨도 이전 노드들은 `front`부터 이어지는 체인에 그대로 남아있어 안 사라짐
  - `dequeue`: `front` 이름표를 다음 노드로 옮김 — 원래 `front`는 아무도 안 가리키게 되어 큐에서 빠짐. 마지막 노드까지 빠지면 `rear`도 같이 `None`으로 맞춰야 함
- **파이썬 내장 큐**: `from queue import Queue` — `put()`(enqueue), `get()`(dequeue, FIFO 순서로 꺼냄)

```python
from collections import deque
q = deque()
q.append(1)     # * enqueue
q.append(2)
print(q.popleft())  # 1 -> 먼저 넣은 게 먼저 나옴(FIFO)
```
- **두 개의 스택으로 큐 만들기**: 스택(LIFO) 두 개를 조합해 큐(FIFO)를 흉내내는 문제
  - 매번 두 스택을 다 뒤집는 방식은 enqueue가 O(n)이 됨
  - **enqueue를 O(1)로**: `s1`엔 그냥 새 값을 쌓기만 함. `dequeue` 시점에 `s2`가 비어있을 때만 `s1`을 통째로 `s2`로 옮겨서(순서 뒤집힘) top이 front가 되게 함
  - `s2`에 남은 걸 dequeue마다 다시 `s1`으로 되돌리면 매번 O(n)이 반복되어 총 O(n²)가 됨 — **옮긴 건 `s2`에 그대로 두고, `s2`가 완전히 빌 때만 다시 채우면** 원소마다 평생 딱 한 번만 이동해서 총 O(n), 즉 amortized(상각) O(1)

## 해시 테이블 (Hash Table)

- **연관 배열(Associative Array)**: "키(key)로 값(value)을 찾을 수 있다"는 개념적 ADT
- **해시 테이블**: 그 연관 배열을 실제로 구현하는 자료구조. 키를 **해시 함수**에 넣어 **해시값**(숫자)을 얻고, 그 값을 배열의 인덱스로 써서 저장/조회 → 평균 O(1)
- **딕셔너리(`dict`)**: 파이썬이 해시 테이블 방식으로 연관 배열 ADT를 구현한 결과물 (`연관 배열` → `해시 테이블` → `dict` 순으로 개념이 구체화됨)
- **해시 충돌**: 서로 다른 키인데 해시값이 같은 경우 발생. 체이닝(같은 자리에 연결 리스트로 여러 개 매달기) 또는 오픈 어드레싱(다른 빈 자리 찾기)으로 해결. 파이썬 `dict`는 오픈 어드레싱 방식

```python
counts = {}
for ch in "hello":
    counts[ch] = counts.get(ch, 0) + 1   # * 없으면 0에서 시작, 있으면 1씩 증가
print(counts)  # {'h': 1, 'e': 1, 'l': 2, 'o': 1}
```

| 문제 | 핵심 아이디어 |
|---|---|
| 문자열 속 문자 수 세기 | 각 문자를 순회하며 `dict`에 없으면 1로 새로 저장, 있으면 값을 1씩 증가 — "값이 있는지 확인 + 없으면 초기화"가 반복되는 전형적인 딕셔너리 활용 |
| 두 수의 합 (brute force) | 이중 반복문으로 가능한 모든 쌍을 다 더해봄 -> O(n²). `j`는 `i+1`부터 시작(자기 자신과 더하는 것 방지, 이전 `i`가 이미 비교한 앞쪽은 다시 안 봄) |
| 두 수의 합 (딕셔너리) | `{숫자: 인덱스}`로 저장 — 찾고 싶은 대상(숫자)을 키로 둬야 `in`으로 O(1) 조회 가능. 매 원소마다 "target을 만들려면 필요한 상대(`rem`)"를 계산해 이미 본 적 있으면 바로 반환, 없으면 지금 숫자를 저장해둠 -> 전체 O(n) |
| 문자열에서 중복 단어 제거 | `set`으로 "이미 나온 단어인지" O(1) 확인하며 처음 나온 단어만 결과 리스트에 남김. `split(" ")`은 리스트를 반환하므로 그 뒤에 문자열 전용 메소드(`.strip()`)를 바로 이어붙일 수 없음(`AttributeError`) — 단어 하나하나에 따로 적용해야 함. `"programmer"`와 `"programmer."`처럼 구두점 때문에 다른 문자열로 취급되는 경우, 비교용으로만 `.strip(".")`한 값을 따로 만들어 쓰고, 결과에 저장할 땐 원본을 그대로 유지해야 구두점이 안 사라짐 |

자세한 예제는 [hash_table.py](hash_table.py) 참고.

## list / set / dict / tuple — 추가·제거 메소드 비교

| 자료구조 | 추가 | 제거 | 비고 |
|---|---|---|---|
| `list` | `.append(값)`(맨 뒤), `.insert(i, 값)`(특정 위치) | `.remove(값)`(값으로), `.pop(i)`(인덱스로) | 순서/인덱스 있음 |
| `set` | `.add(값)` | `.remove(값)` / `.discard(값)` | 순서/인덱스 없음, 중복 자동 방지. 빈 set은 `{}`가 아니라 `set()`으로 만들어야 함(`{}`는 빈 dict) |
| `dict` | `딕셔너리[키] = 값` (대입으로 추가, `append` 없음) | `del 딕셔너리[키]` / `.pop(키)` | 키-값 쌍 |
| `tuple` | 없음 | 없음 | 변경 불가(immutable) — 추가/삭제 메소드 자체가 없음 |

`list`는 "순서상 뒤에 덧붙인다"는 의미라 `append`, `set`은 순서가 없고 "이 원소가 있다/없다"만 중요해서 `add`로 이름이 다름.

## 이진 트리 (Binary Tree)

- **용어**: 루트(맨 위 노드) / 자식·부모·형제 노드 / 리프 노드(자식 없음) / 브랜치 노드(자식 있음)
- **서브트리(Subtree)**: 트리 안의 어떤 노드 하나 + 그 노드의 자손 전부를 떼어놓은 것. 자식이 없는 노드 하나만 있어도(크기 1) 서브트리로 인정됨. 트리 안 노드 개수만큼 서브트리가 존재함(각 노드가 자신을 루트로 하는 서브트리를 하나씩 가짐)
- **이진 트리**: 각 노드가 자식을 최대 2개(왼쪽/오른쪽)만 가질 수 있음. 왼쪽/오른쪽에 어떤 값이 와야 하는지는 규칙이 없음
- **이진 탐색 트리(BST)**: 이진 트리 + "왼쪽 자식은 항상 나보다 작고, 오른쪽 자식은 항상 나보다 크다"는 규칙 추가. 이 규칙 덕분에 비교 한 번마다 안 볼 절반을 통째로 버릴 수 있어 탐색이 O(log n)(단, 트리가 균형 잡혀있을 때만 — 한쪽으로 치우치면 최악 O(n))

```python
class BinaryTree:
    def __init__(self, value):
        self.value = value
        self.left_child = None
        self.right_child = None

root = BinaryTree(10)
root.left_child = BinaryTree(5)   # * 왼쪽 자식 직접 조립
root.right_child = BinaryTree(15)
```
- **DOM**: HTML 문서를 트리로 표현한 모델. 태그의 중첩 관계가 그대로 부모-자식 관계가 됨
- **insert_left/insert_right**: 일반 이진 트리는 "어디에 넣어야 하는지" 규칙이 없어서, 이미 자식이 있는 자리에 삽입하면 새 노드를 그 사이에 끼우고 원래 있던 서브트리는 한 단계 밀어냄(데이터 유실 방지). 실전에서는 보통 이런 메서드 없이 트리 모양을 알고 있는 상태에서 `.left_child = BinaryTree(값)`처럼 직접 조립함
- **DFS(깊이 우선 탐색)**: 한쪽으로 끝까지 파고들었다가 막히면 되돌아와서 다른 방향 시도. 보통 재귀로 구현. 백트래킹(선택 시도 → 안 되면 되돌아가기)이 트리에서 자주 쓰이는 이유도 이 구조와 똑같기 때문
- **BFS(너비 우선 탐색)**: 같은 레벨(층)을 옆으로 다 본 뒤 다음 레벨로 내려감. 큐로 구현 — `current`(이번 레벨)를 다 처리하면서 자식들을 `next`(다음 레벨)에 모아뒀다가, 그 레벨이 끝난 뒤에야 `current = next`로 한 번에 교체
- **DFS 순회 3종류**: 자기 자신을 방문(출력)하는 시점만 다르고 재귀 구조는 동일
  - 전위(Preorder): 나 → 왼쪽 → 오른쪽
  - 중위(Inorder): 왼쪽 → 나 → 오른쪽 (BST에서 하면 오름차순 정렬 순서로 나옴)
  - 후위(Postorder): 왼쪽 → 오른쪽 → 나
  - 순회 함수를 클래스 메서드가 아니라 독립 함수로 짜는 이유: 재귀 기저 조건에서 `None`을 그대로 받아 처리해야 하는데(`if tree: ...`), 메서드로 만들면 자식 없는 곳에서 `None.메서드()`를 호출하게 되어 `AttributeError` 발생
- **이진 트리 뒤집기(Invert)**: 모든 노드에서 왼쪽/오른쪽 자식을 서로 스왑. 스왑을 재귀 호출 전에 하든 후에 하든 결과는 같음(모든 노드를 한 번씩 방문해서 바꾸기만 하면 되는 문제라 순서 자체는 안 중요함) — BFS로도, DFS로도 구현 가능

자세한 예제는 [binary_tree.py](binary_tree.py) 참고.

## 이진 힙 (Binary Heap)

- **완전 이진 트리 + 힙 속성**을 만족하는 자료구조. 완전 이진 트리라서 포인터 없이 **배열(리스트)만으로 구현** 가능 — 인덱스 `i`일 때 부모는 `(i-1)//2`, 왼쪽 자식은 `2i+1`, 오른쪽 자식은 `2i+2`
- **최소 힙(Min-Heap)**: 부모가 항상 자식보다 작거나 같음 → 루트가 전체 최솟값
- **최대 힙(Max-Heap)**: 부모가 항상 자식보다 크거나 같음 → 루트가 전체 최댓값
- BST와 달리 **위-아래(부모-자식) 관계만** 규칙이 있고, 좌우(형제) 관계는 순서 상관없음
- 삽입/삭제 모두 트리 높이만큼만 움직이면 돼서 O(log n), 루트(최솟값/최댓값) 확인은 O(1)
- **키(key)와 우선순위(priority)**: 원래는 별개 개념(우선순위 큐에서 "얼마나 급한지"를 나타내는 값)이지만, 키 자체가 숫자/문자처럼 산술적으로 비교 가능하면 그 값을 그대로 우선순위로 사용 가능. 비교 불가능한 객체를 저장할 땐 별도의 우선순위 필드를 따로 둬야 함

```python
heap = [1, 3, 5, 7, 9]
i = 1
print(heap[(i - 1) // 2])  # heap[0] = 1 -> 부모
print(heap[2 * i + 1])     # heap[3] = 7 -> 왼쪽 자식
```

### `heapq` 모듈 (파이썬 내장, 최소 힙 전용)

| 함수 | 하는 일 |
|---|---|
| `heapify(리스트)` | 리스트를 최소 힙 구조로 그 자리에서(in-place) 재배열. **반환값 없음**(`None`) |
| `heappop(리스트)` | 루트(최솟값)를 꺼내면서 자동으로 재정렬까지 함 — 맨 끝 값을 루트로 옮긴 뒤 더 작은 자식과 비교하며 내려보냄("heapify down"). **꺼낸 값을 반환함** |
| `heappush(리스트, 값)` | 값을 맨 끝에 넣고 부모와 비교하며 위로 올려보냄("heapify up") 후 자동 재정렬. **반환값 없음**(`None`) |

- **pop은 반환값이 있고 push는 없는 이유**: pop은 자료구조 안에 있던 값을 밖으로 꺼내는 동작이라 그 값을 호출한 쪽에 돌려줘야 하지만, push는 이미 넣으려는 값을 손에 쥔 채로 호출하는 것이라 다시 돌려받을 필요가 없음 — `list.pop()`/`list.append()`, 스택/큐의 push/pop도 전부 같은 패턴
- **최대 힙 만들기**: `heapq`는 최소 힙만 지원. 숫자는 값에 `-1`을 곱해서 넣었다가 꺼낼 때 다시 `-1`을 곱하면 최대 힙처럼 동작. 문자열은 `-1`을 곱할 수 없어서 이 트릭이 안 통함 → 직접 클래스를 만들어 비교 부등호(`>`)를 반대로 써야 함
- **우선순위 큐로 쓰기**: `(우선순위, 값)` 튜플을 저장하면, 튜플은 첫 번째 요소부터 비교하므로 우선순위 기준으로 자동 정렬됨

### 최소 비용으로 로프 연결하기 (그리디 + 힙 활용 예제)

- 길이가 다른 로프 여러 개를 한 쌍씩 이어붙여 하나로 합칠 때, 두 로프를 잇는 비용은 "두 로프 길이의 합"이고 전체 비용은 그 비용들의 총합
- **항상 가장 짧은 로프 2개부터 먼저 합쳐야 총 비용이 최소**가 됨(그리디 전략) — 합쳐진 값은 이후 다시 비용에 포함되므로, 짧은 값을 먼저 처리해서 빨리 큰 값으로 만들어버리는 게 유리
- 매번 "가장 짧은 것"을 O(log n)에 뽑아야 하니 최소 힙이 정확히 들어맞음: `heapify` → (`heappop` 2번 → 합 → `heappush`) 반복 → 힙에 1개만 남으면 종료

### 리스트가 이미 최소 힙인지 확인하기

- **원본을 건드리지 않고 확인**하는 게 핵심: `heapify()`는 원본 리스트를 직접 재배열해버리므로, `tree.copy()`로 복사본을 만들어 그 복사본만 `heapify()`하고 원본과 비교해야 함
- 원본이 이미 힙 순서였다면 `heapify()`해도 바뀌는 게 없으므로 원본과 복사본이 똑같음 → `True`. 힙이 아니었다면 재배열로 순서가 바뀌어 서로 달라짐 → `False`

```python
def is_min_heap(tree):
    heap = tree.copy()
    heapify(heap)
    return tree == heap
```

- **직접 클래스로 구현하는 경우**(`heapq` 없이): 모든 부모-자식 쌍에서 "부모 ≤ 자식"이 성립하는지 인덱스로 직접 순회하며 확인. 자식이 있는 노드까지만 확인하면 되고, 자식 인덱스가 리스트 범위를 벗어나면(`인덱스 < len(리스트)`) 그 자식은 없는 것으로 처리

자세한 예제는 [binary_heap.py](binary_heap.py) 참고.

## 그래프 (Graph)

- 노드(정점)와 그 사이를 잇는 연결선으로 이루어진 비선형 자료구조. 지금까지 배운 트리도 사실 그래프의 한 종류(사이클이 없는 그래프)

### 구성 요소

| 용어 | 의미 |
|---|---|
| 노드(Node) / 정점(Vertex) | 그래프를 이루는 하나의 데이터 단위 |
| 키(Key) | 각 노드의 이름 — 노드를 구분하는 식별자 |
| 페이로드(Payload) | 키 외에 그 노드가 추가로 들고 있는 데이터 |
| 에지(Edge) / 간선 | 노드와 노드를 잇는 연결선 |
| 가중치(Weight) | 에지에 매겨진 비용/거리 값 (예: 두 도시를 잇는 도로의 거리) |

### 그래프 종류

- **방향 그래프(Directed Graph)**: 에지에 방향이 있음 — A → B로만 갈 수 있고 B → A는 안 될 수 있음 (예: 팔로우 관계, 일방통행 도로)
- **무방향 그래프(Undirected Graph)**: 에지에 방향이 없음 — 연결돼 있으면 양쪽 다 오갈 수 있음 (예: 친구 관계, 양방향 도로)
- **완전 그래프(Complete Graph)**: 모든 정점 쌍이 서로 에지로 직접 연결된 그래프 — 정점이 n개면 에지는 `n(n-1)/2`개(무방향 기준)
- **불완전 그래프(Incomplete Graph)**: 완전 그래프의 반대 — 직접 연결 안 된 정점 쌍이 하나라도 있는 그래프. 실제로 다루는 그래프는 대부분 이쪽(모든 정점을 다 이을 필요는 없으므로)

### 경로(Path)와 사이클(Cycle)

- **경로(Path)**: 한 노드에서 다른 노드까지, 실제로 존재하는 에지를 따라가며 거치는 노드들의 나열 (예: `A→B→C→D`). 방향 그래프면 에지 방향도 지켜야 함
  - 경로 길이 = 지나간 에지 개수, 경로 비용 = 지나간 에지들의 가중치 합
  - 단순 경로(Simple Path): 같은 노드를 두 번 이상 거치지 않는 경로
- **사이클(Cycle)**: 어떤 노드에서 출발해서 에지를 따라가다가 다시 그 노드로 돌아오는 경로
- **비순환 그래프(Acyclic Graph)**: 사이클이 하나도 없는 그래프
- **DAG(Directed Acyclic Graph, 방향 비순환 그래프)**: 방향 그래프이면서 사이클이 없는 그래프 — 지금까지 배운 트리도 DAG의 한 종류(부모→자식 방향만 있고 절대 순환 안 됨)

### 그래프를 코드로 표현하는 방법

| 방식 | 설명 |
|---|---|
| 에지 리스트(Edge List) | 에지 하나하나를 `(노드1, 노드2)` 쌍으로 나열. 구현 제일 단순하지만, 특정 노드와 연결된 노드들을 찾으려면 리스트 전체를 훑어야 함(O(E)) |
| 인접 리스트(Adjacency List) | 각 노드가 자기와 연결된 노드 목록을 직접 들고 있음. 실무에서 가장 흔하게 쓰임 |
| 인접 행렬(Adjacency Matrix) | 노드 × 노드 크기의 2차원 배열로 연결 여부(또는 가중치)를 표시 |

```python
edge_list = [("A", "B"), ("A", "C")]                      # * 에지 리스트
adjacency_list = {"A": ["B", "C"], "B": ["A"], "C": ["A"]}  # * 인접 리스트
adjacency_matrix = [[0, 1, 1], [1, 0, 0], [1, 0, 0]]        # * 인접 행렬 (A,B,C 순서)
```

### 인접 리스트의 시간복잡도

| 연산 | 시간복잡도 | 이유 |
|---|---|---|
| 노드 추가 | O(1) | 딕셔너리에 새 키 하나 추가하고 빈 리스트로 초기화하기만 하면 됨 |
| 에지 추가 | O(1) | 각 노드의 리스트 맨 뒤에 `append`만 하면 됨 |
| 특정 노드의 이웃 조회 | O(1) | 딕셔너리 키 조회라서 바로 찾음 |
| 두 노드가 직접 연결됐는지 확인 | O(V) (V = 그 노드의 이웃 수) | 그 노드의 리스트를 순회하며 찾아야 함 |

### 그래프를 실무에서 쓰는 곳

- **길찾기/내비게이션**: 지도의 교차로/지점이 노드, 도로가 에지(가중치=거리·시간). 최단 경로 알고리즘(다익스트라 등)으로 최적 경로 계산
- **SNS 친구/팔로우 관계망**: 사람이 노드, 관계가 에지 — "친구의 친구 추천", "몇 단계 건너 아는 사이인지" 등에 그래프 탐색 사용
- **웹페이지 링크 구조**: 페이지가 노드, 링크가 에지 — 구글 페이지랭크처럼 검색 순위 계산에 활용
- **네트워크 라우팅**: 라우터/서버가 노드, 회선이 에지 — 데이터가 어느 경로로 가야 가장 빠른지 계산
- **의존성 관리**: 패키지/모듈이 노드, "A가 B를 필요로 한다"가 에지(방향 그래프, DAG) — 설치 순서, 빌드 순서 결정에 사용

### 클래스로 인접 리스트 구현하기 (`Vertex`, `Graph`)

- **`Vertex` 클래스**: 점(노드) 하나를 표현. `key`(이름표) + `connections`(자신과 인접한 노드들을 담는 딕셔너리)를 가짐
  - `connections`는 노드마다 완전히 별개(각자 자기 것만 가짐) — `{인접 Vertex 객체: 가중치}` 형태로 저장. 리스트가 아니라 딕셔너리인 이유는 가중치까지 같이 저장하기 위함
  - `add_adj(vertex, weight)`: 인접한 노드(Vertex 객체)와 가중치를 `connections`에 추가
  - `get_connections()`: `connections.keys()` → 인접한 노드(Vertex 객체)들만 조회
  - `get_weight(vertex)`: 특정 인접 노드까지의 가중치 조회
- **`Graph` 클래스**: 전체 그래프를 관리하는 역할. `vertex_dict`(이름 → Vertex 객체를 찾기 위한 주소록)를 가짐
  - `add_vertex(key)`: 새 `Vertex` 객체를 만들어 `vertex_dict`에 등록
  - `get_vertex(key)`: 이름으로 등록된 `Vertex` 객체를 찾아 반환 (없으면 `None`)
  - `add_edge(f, t, weight)`: f, t가 없으면 자동으로 만든 뒤, f의 `Vertex` 객체에게 `add_adj()`를 호출해 t와 연결시킴 — **f의 `connections`에만 저장되는 한쪽 방향**이라 무방향으로 쓰려면 반대 방향도 한 번 더 호출해야 함
- 실제 "연결 정보"는 `Graph`가 아니라 **각 `Vertex` 객체가 개별적으로** 들고 있음 — `Graph`는 그 `Vertex`들을 찾아주고 연결을 시켜주는 관리자 역할만 함

```python
g = Graph()
g.add_edge("A", "B", 5)   # * A, B가 없으면 자동 생성 후 A->B를 가중치 5로 연결
a = g.get_vertex("A")
for neighbor in a.get_connections():
    print(neighbor.key, a.get_weight(neighbor))  # B 5
```

## 다익스트라(Dijkstra) 알고리즘

- **가중치 있는 그래프에서, 한 시작점으로부터 다른 모든 노드까지의 최단 거리를 구하는 그리디 알고리즘**. "데이크스트라"라고도 표기(같은 알고리즘, 표기 차이일 뿐)
- 핵심 그리디 원칙: **"방문 안 한 노드 중 지금까지 알려진 거리가 가장 짧은 노드를 항상 먼저 방문한다."** 가중치가 전부 0 이상이라면, 이렇게 고른 노드의 거리는 더 짧아질 수 없으므로 그 순간 바로 최종 확정 가능(더 먼 노드를 거쳐서는 절대 더 짧아질 수 없기 때문)
- **초기화**: 시작점만 거리 0, 나머지 노드는 전부 `float("infinity")`(무한대)로 세팅 — "아직 그 노드까지 가는 길을 하나도 못 찾았다"는 상태를 표현. 실제 경로를 찾을 때마다 그보다 작은 값으로 자연스럽게 갱신됨
- **우선순위 큐(최소 힙) 활용**: "다음에 방문할, 거리가 가장 짧은 노드"를 매번 빠르게(O(log n)) 뽑기 위해 최소 힙을 씀. `(거리, 노드)` 튜플로 큐에 저장 — 파이썬은 튜플을 비교할 때 첫 번째 값부터 비교하므로, 거리를 앞에 둬야 거리 기준으로 자동 정렬됨
- **`graph`(원래 주어진 가중치 정보, 고정불변)와 `distances`(지금까지 알아낸 최단 거리 기록, 계속 갱신됨)는 서로 다른 딕셔너리**임에 주의 — `graph`는 절대 무한대가 아니라 처음부터 확정된 값

```python
def dijkstra(graph, starting_vertex):
    distances = {vertex: float("infinity") for vertex in graph}
    distances[starting_vertex] = 0
    pq = [(0, starting_vertex)]

    while len(pq) > 0:
        current_distance, current_vertex = heapq.heappop(pq)
        if current_distance > distances[current_vertex]:
            continue  # * 이미 더 짧은 값으로 갱신된 낡은 후보 -> 무시하고 다음 반복으로

        for neighbor, weight in graph[current_vertex].items():
            distance = current_distance + weight
            if distance < distances[neighbor]:  # * 더 짧은 경로를 새로 찾았으면
                distances[neighbor] = distance   # * 기록 갱신
                heapq.heappush(pq, (distance, neighbor))  # * 다음 방문 후보로 큐에 등록

    return distances
```

- **`if current_distance > distances[current_vertex]: continue`가 필요한 이유**: 같은 노드가 큐에 중복으로 들어갈 수 있음(더 짧은 경로가 나중에 발견되는 경우). 이미 더 짧은 값으로 확정된 뒤에 낡은(더 큰) 후보가 나중에 큐에서 나오면, 그건 무시하고 건너뛰어야 함
- 반복은 큐가 빌 때(`len(pq) == 0`)까지 계속됨 — 매 반복마다 "지금 가장 가까운 노드"를 꺼내서, 그 노드를 거쳐 이웃들에 더 빨리 갈 수 있는지 확인하고 갱신하는 과정을 반복
